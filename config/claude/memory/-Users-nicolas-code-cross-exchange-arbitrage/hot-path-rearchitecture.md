Hot-path performance re-architecture (started 2026-07-15, branch nicolasMazuryk/interview-before-task). Prod baseline: ELU 0.70, 85 GCs/10s, EL p99 16.6ms.

**Locked user decisions:** worker_threads sharding (one ingest worker per exchange, main thread keeps arbitrage/Redis/trading); tracing dropped from hot path entirely (created only at opportunity emission in `ArbitrageEngine.scanOpportunities`); no test framework (verify via PerformanceMonitor + live runs); conflation/backpressure explicitly out of scope.

**Phase 0+1 shipped:** `hotPathCounters` drained into PerformanceMonitor flush line; `bookMerge.ts` in-place binary-search delta merge (bids desc / asks asc, snapshot path self-heals unsorted sides); persistent mutated TopOfBook per (exchange,symbol) — emitted object valid only during synchronous emit tick (all consumers audited: copy scalars synchronously); shared `parseLevels` helper; engine scratch reuse (legs array + 4 DepthSimulationResult). Dev-machine result: ELU 0.47→0.32, GC 53-78→21-22 per 10s.

**Phase 2 shipped (2026-07-15):** per-exchange ingest workers own WS connections (`src/ingest/{protocol,ingestWorker,ingestWorkerHost}.ts`); `BookMirror extends OrderbookManager` (maps made protected — zero consumer type churn), decodes transferable Float64Array book messages by mutating persistent levels; worker reuses adapter classes + its own OrderbookManager for bookMerge/top-price gate; host restarts with backoff + `resetBooks` mirror clear; `ingest.enabled` YAML flag = rollback lever (dev+spread.production true, funding.production defaults false). Spike proved all 4 vendor SDKs survive forced socket kills in a worker. Also fixed pre-existing bug: `Orchestrator.shutdown()` was a no-op under signal handler (isShuttingDown set before call tripped its own guard) — now gated on separate `shutdownStarted` flag. Dev-machine result: main ELU 0.46→0.22-0.26, main GC ~51→~38 per 10s, hop latency ~1-5ms mean, kill-test + graceful shutdown verified live.

**Phase 3 shipped (2026-07-15):** `ingest.workers: [{exchange, marketType?}]` topology — validated at config load (unknown exchange/type, duplicates, all-types+typed overlap all throw); unlisted exchanges get one all-types worker; split worker gets `wsConfig.marketType` (base.ts filterMarketType) + pre-filtered MarketLite list; orchestrator warns on market types no worker covers. `clearExchangeBooks(exchange, marketType?)` scoped via `getMarketTypeFromUnifiedSymbol` (symbol-derived, books don't store type) so a split worker's restart/reset never nukes sibling books — verified live: killed bybit:spot worker, only spot books dropped, linear survived, restart 2.6s. Worker metrics folding: `workerSamples` registry (`src/core/monitoring/workerSamples.ts`, counters add / gauges set) drained into main perf line as `workers:{'bybit:spot':{eluPct,gc,book_msgs_out,...}}`; worker PerformanceMonitor `onSample` callback ships PerfSample (per-thread signals only — no userPct/systemPct, process.cpuUsage is process-wide) in `metrics` msg; replaced old flat `w_<exchange>_` prefix counters. dev yaml runs bybit split spot+linear (359/596 markets, ELU 0.15-0.20 / 0.26-0.33); spread.production has commented example. `ingestHosts` keyed by worker label.
